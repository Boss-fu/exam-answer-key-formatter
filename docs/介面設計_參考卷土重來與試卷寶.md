# OCR 介面設計：參考卷土重來與試卷寶

> 設計目的：把掃描卷從上傳、OCR 處理、人工覆核到 Word 下載，收斂成一條可中斷、可回來修正的流程。僅參考畫面結構與操作流程；不使用對方程式碼、商標、圖示或其他素材。
>
> 截圖代號：卷土重來 `Z01`–`Z09` = `ocr/results/ui_frames/zizi/f01.jpg`–`f09.jpg`；試卷寶 `S01`–`S06` = `ocr/results/ui_frames/shijuanbao/f01.jpg`–`f06.jpg`。`S01` 被 Safari 常用網站面板遮住，僅能確認其背後首頁版型，不能據此推斷元件細節。

## A. 參考產品的畫面結構與互動

|---|---|---|---|
| 任務入口 | 首頁已有三步籤（轉 Word／題庫檔／詳解）與上傳。 | OCR 後沒有同一條可回看的「考卷工作」流程。 | 已相近；保留三步籤，但第一步要延展為完整流程。 |

## C. 新介面規格

### 1. 頁面流程與狀態

第一步「掃描卷轉 Word」改為有持續工作 ID 的五段流程；題庫檔與詳解保留為原有的第二、三步獨立任務，不把 API 或功能混合。

1. **上傳**：選 PDF／JPG／PNG，保留目前選檔與「開始轉檔」；顯示檔名、頁數（取得後）、所選主機、可接受格式與個資／本機處理提示。
2. **處理進度**：顯示「上傳、轉正與清筆跡、辨識與切題、Word 組版」四個階段；顯示已完成頁／總頁、耗時、目前頁縮圖（有資料才顯示）。可離開結果頁後由工作清單回來；不允許把瀏覽器關閉描述成背景保證，除非後端確有此能力。
3. **對照預覽**：處理完成直接進入結果頁。左為原稿，右為 OCR／去筆跡預覽；上方有頁面縮圖列、頁碼、問題摘要（低信心字、題數、圖、表格、待確認）。使用者可切換「整頁」「文字／題目」檢視。
4. **逐頁／逐題修正**：在結果頁直接提供「修正筆跡」與「修正題目」；點擊後在同一工作 ID、同一頁／題開啟抽屜或全螢幕工作台。筆跡修正沿用雙畫布、消除／還原、筆刷、縮放、存檔並下一頁；題目修正沿用行號、新題、雜訊、文字改正、儲存標註、重建 Word。儲存後回到對照預覽，刷新該頁與待確認數。
5. **下載 Word**：完成區先呈現「可下載」與「尚有 N 項待確認」；保留茲茲格式 Word、確認清單、辨識原文、裁圖單張／ZIP，並在同一區保留重新產生 Word。題庫流程的 Word／CSV、詳解流程的 Word 必須繼續各自提供下載。

### 3. 元件清單與行為

| 元件 | 行為與必要條件 |
|---|---|
| 頁首主機控制 | 延用 `serverSelect`、自訂主機、健康檢查、連線徽章、重試與本機服務入口；任一工作建立後須顯示其原始主機，避免切換主機後下載到錯誤位置。 |
| OCR 工作步驟列 | 純導覽／狀態元件，未完成步驟不可偽裝成已完成；可回到已完成步驟，保留工作資料。 |
| 上傳卡 | 檔案選擇、拖放（可新增）、開始轉檔、格式與檔案驗證；按下後鎖定重複送出，但保留錯誤重試。 |
| 進度卡 | 階段名稱、頁數、百分比／不確定時顯示工作中、耗時與錯誤訊息；沒有後端頁級進度時，先只顯示真實可得的階段，不假造精準百分比。 |
| 對照檢視器 | 同步捲動／縮放為預設、可解除同步；原稿與處理結果永遠標清楚；頁縮圖、前後頁鍵、鍵盤左右鍵、頁碼跳轉。 |
| 待確認側欄 | 由既有 `reviewText`、確認清單與低信心資料聚合；可點選後定位頁／題。 |
| 筆跡修正工具 | 整合 `label.html` 的 `/api/label/upload`、`render`、`save-mask`、筆刷、消除／還原、縮放、前後頁與儲存；新增「從目前 OCR 工作帶入」介面契約前，不能移除原始 PDF 上傳入口。 |
| 題目修正工具 | 整合 `/api/label/list`、`draft`、`save-questions`、`rebuild`；行資料顯示頁碼／題號上下文，保留新題、雜訊、改字和重建 Word。 |
| 下載區 | OCR：`docxUrl`、`reviewUrl`、`txtUrl`、圖片連結；手動裁圖維持單張下載、刪除、ZIP。題庫：考卷 Word、CSV、CSV 轉 Word。詳解：上傳／擷取、產生、官方答案比對、逐題展開、Word 下載。 |
| 無障礙與錯誤 | 所有圖示按鈕有文字或 `aria-label`；鍵盤焦點可見；處理、連線、儲存以 `role=status` 宣告；色彩不是唯一狀態訊號。 |

## D. 分階段實作與驗收

| 階段 | 可獨立上線內容 | 驗收方式 |
|---|---|---|
| 0：盤點與契約測試 | 為現有三條流程與 `label.html` API 建立手動測試清單／自動冒煙測試；不改視覺。 | 對每個現有按鈕至少驗證一次可觸發正確端點或本機 UI 行為；比對改前、改後端點清單一致。 |
| 1：OCR 流程殼 | 僅重排第一步為上傳、真實進度、結果容器、工作步驟列；原本結果內容先原封不動放入下載區。 | PDF、JPG、PNG 各一份：可選檔、送 `/api/py-ocr`、錯誤可重試、完成後四類既有結果仍可下載／查看；手機 375px、平板 768px、桌面 1280px 截圖檢查。 |
| 2：結果對照預覽 | 建立頁縮圖、原稿／結果雙欄與待確認列表；資料不足時先明示「此工作尚無頁面預覽」，不偽造結果。 | 用多頁測試卷驗證換頁、同步捲動／縮放、待確認定位；人工比對原稿和結果，確認沒有遮蔽題目或使下載退化。 |

## 設計決策摘要

- 以「左原稿、右結果」作為 OCR 完成後的預設畫面，讓品質判斷不再只依文字狀態。
- 修正功能從外連工具提升為結果頁的上下文操作，但保留獨立入口，避免整合初期阻斷既有工作。
- 以既有酒紅、米白、淡綠、淺黃 token 延續茲茲識別；不仿用參考產品的商標素材或名稱。
- 進度只呈現後端實際能提供的資訊；若尚未有分頁進度，先做誠實的階段狀態。
- 「待確認」是下載前的透明提示，不是硬性封鎖；教師仍可依工作需求先下載草稿。
