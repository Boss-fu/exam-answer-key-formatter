# 卷土重來 創造邏輯拆解 ＋ 我們的優化藍圖

> 目的：把俊瑋（高中部主任）做的「卷土重來」整套方法學起來，整理成可複製的心法，
> 然後做一個**參考他、但更好**的版本。核心信念：AI 沒有聰不聰明，只有**方法、資料、模型組合**下得好不好；
> 我們不一定要原創，但要會**模仿 → 優化 → 超越**。
>
> 本文根據他 clone 給我們的檔案（CLAUDE.md、README、requirements、get_models、pairs_build、
> dehand_train/eval、formula_try、desktop 等）＋附上的模型（det/rec/dehand.onnx）拆解而成。

---

## 一、為什麼他「一次就做完」——六條創造心法

這才是重點。他的強不在寫 code，而在**選對打法**：

1. **不自己造模型，組裝開源 ONNX。**
   OCR 用 PP-OCRv5、公式偵測用 Pix2Text MFD(YOLOv8)、公式辨識用 RapidLaTeXOCR——全是別人訓練好、
   Apache/AGPL 授權、CPU 能跑的現成模型。他只做「接線」與「規則」。**我們也該這樣：先找現成模型，別從零訓練。**

2. **把公司既有資產變成免費訓練資料。**（最聰明的一招，見第三節）
   去筆跡模型需要「有筆跡 vs 乾淨」的成對資料。茲茲本來就會把考卷做成乾淨版——他就拿
   「原稿掃描 ↔ 自己做好的乾淨版」自動對齊相減，筆跡差異就是標註，**完全不用人工框一個字**。

3. **小模型 + 把商業規則寫進 loss。**
   去筆跡只是一個 1.5MB 的小 U-Net，CPU 就能訓練。而且「寧可少擦不可傷印刷」這條鐵律，
   他直接寫成 loss：擦到印刷字的懲罰 ×3，再挑「印刷誤擦 < 0.5%」下召回最高的門檻。**規則不是寫在註解裡，是寫進數學裡。**

4. **用「評測迴圈」當訓練，不追求一次到位。**
   `dehand_eval.py`、`regress.py`、`diag.py` 一直在量「召回率 / 誤擦率 / 題數對不對」。
   改規則 → 跑分 → 看數字 → 再改。**這跟我們 ocr/run_eval.py 的想法一樣，要繼續強化。**

5. **硬限制逼出乾淨架構。**
   老闆三條鐵律：不呼叫任何 API、CPU-only、記憶體 <2GB。看似綁手，其實逼他把每個環節都挑
   「本地、輕量」方案，反而好部署、零成本、考卷不外流。**我們現在的 Claude 引擎正好違反第一條，要換掉。**

6. **一份引擎、兩種上線。**
   同一個 FastAPI，桌面版用 PyInstaller + Edge 應用程式視窗（免登入、不上傳）、
   主機版加密碼 + HF Spaces / Cloudflare Tunnel。**不綁 Tailscale，員工任何地方開瀏覽器就能用。**

## 二、技術堆疊逐層拆解

對照 `README` 的流程表，每一層「用什麼、為什麼」：

| 階段 | 他的做法 | 用到的工具／模型 | 為什麼這樣選 |
|---|---|---|---|
| PDF→圖 | 300dpi 灰階 | PyMuPDF | 灰階省記憶體，OCR 不需要彩色 |
| 清紅藍筆、灰底拉白 | 彩色通道分離 + 形態學 | OpenCV | 老師批改多是紅藍筆，先清掉再 OCR |
| 去手寫（黑筆） | 小 U-Net 推論遮罩 → 擦白 | 自訓 `dehand.onnx` | 黑筆跟印刷一樣黑，規則擦不掉，只能學 |
| 文字辨識（繁中） | 偵測框 det + 辨識 rec + 轉繁 | PP-OCRv5 ONNX + OpenCC(s2twp) | 繁中掃描卷 Tesseract 太差；PP-OCRv5 強很多 |
| 雙欄、閱讀順序 | 找中間垂直分隔線 | OpenCV 投影 | 考卷幾乎都雙欄，順序錯整份就廢 |
| 表格 | 偵測格線 → 重建 Word 表格 | OpenCV | 保留合併儲存格 |
| 附圖 | 扣掉文字後的大塊圖形 + 座標標籤 | OpenCV 連通域 | 圖不重畫，裁下來插回原位 |
| 公式 | MFD 偵測公式框 → 每框轉 LaTeX | Pix2Text MFD + RapidLaTeXOCR | 分式/根號/上下標 OCR 會壞，要專門模型 |
| 切題目 | 題號/(A)(B)/「一、單選題」/題組規則 | 純規則 | 結構判斷不需要 AI |
| 卷頭 | 判學年/學期/年級/科目/段次/學校 | 純規則 | 決定檔名與橫幅 |
| 排版 | 茲茲範本（自動編號、定位點、橫幅） | python-docx + buildlib + `template.docx` | 跟我們 exam-to-word 技能同源 |

**速度**：雙欄 A4 每頁約 15–30 秒（CPU）。我今天用他的 PP-OCRv5 模型實測，單欄 3.2 秒（見第七節）。

## 三、最關鍵一招：去筆跡訓練資料「無中生有」（`pairs_build.py`）

一般做去筆跡要人工一個字一個字標，貴到做不起來。他的解法：

1. **配對**：`原稿`（有學生作答/老師批改的掃描）↔ `乾淨版`（茲茲本來就做好的印刷版）。
2. **對齊**：先依方向轉正，同尺寸直接比；不同尺寸先縮放，再用 **ORB 特徵點 + Homography 透視變換**
   把乾淨版貼到原稿座標上（處理試卷寶的裁邊、拉正）。
3. **驗證對齊**：算「乾淨版的墨跡在原稿同位置也有墨跡」的一致度，**< 0.85 直接丟掉**（怕配錯檔）。
4. **相減得標註**：`原稿有墨 且 乾淨版該處是白的` → 那就是手寫。各自用 Otsu 門檻（乾淨版常被調深、
   原稿偏灰，固定門檻會失準），還留 1 像素容差，避免把印刷字邊緣誤標成手寫。
5. 每頁輸出 `x.png`(原稿灰階) + `m.png`(手寫遮罩)，全自動、零人工。

> **心法**：要訓練資料時，先問「公司有沒有現成的成對資料可以自動對齊相減出標註」。
> 茲茲的乾淨版庫存＝金礦。

## 四、去筆跡模型怎麼訓練（`dehand_train.py`）

- **模型**：U-Net，通道 (16,32,64,96)，小到 CPU 可訓。輸入 150dpi 灰階、256×256 patch。
- **資料增強**：七成挑有手寫的位置；加縮放、明暗、雜訊、模糊（模擬手機照片、淡掃描）。
- **把鐵律寫進 loss**：`印刷墨跡上的誤判懲罰 ×3`（v1）。loss = 加權 BCE + 0.5×Dice。
- **門檻挑選**：驗證集上掃 0.3~0.95，挑「**印刷誤擦 < 0.5%** 下召回最高」的門檻，寫進 `dehand.json`。
- **切驗證集依整份考卷**（同一份的試卷寶版與乾淨版不跨 train/val），避免偷看。
- 匯出 `dehand.onnx`（opset 17）。他給的 `dehand.json`：門檻 0.5、召回 36.2%、印刷誤擦 0.49%。

> 36% 召回聽起來不高，但那是**刻意保守**——寧可只擦掉三分之一手寫、也不碰壞任何一個印刷字。
> 剩下的靠「有空白原卷就用空白原卷」＋人工確認清單補。

## 五、公式：偵測 + 辨識兩段（`mfd_try.py` + `formula_try.py`）

1. **偵測**：MFD（Pix2Text 的 YOLOv8，`mfd.onnx` 約 220MB，`get_models.py` 下載）框出頁面上哪裡是公式。
2. **辨識**：每個框丟 **RapidLaTeXOCR** → LaTeX。他把輸出長度上限從 512 調到 200，避免辨識失敗時
   一直重複吐字卡 40 秒。
3. **轉 Word**：LaTeX → OMML（Word 原生公式）或保留 `$...$` 給 MathType。

> 這正好補我們 pyexam.py 最大的洞——我的版本公式直接壞掉；他是「專門模型處理公式」。

## 六、上線與打包（`desktop.py` / `installer.iss` / HF Spaces）

- **桌面版**：`desktop.py` 用 PyInstaller 打包成 exe，開 **Edge `--app` 應用程式視窗**（沒有網址列、像一般軟體），
  引擎只在 `127.0.0.1` 跑、免登入、考卷不上傳；閒置 3 分鐘自動關。Inno Setup 做安裝檔。
- **主機版**：FastAPI + 必設 `APP_PASSWORD`，單執行緒排隊。
- **線上首選 Hugging Face Spaces**（免費 CPU、Docker SDK），備案辦公室電腦 + Cloudflare Tunnel。
- **課務系統的 Render 只有 512MB，OCR 放不進去**——所以 OCR 一定獨立部署。

## 七、我們現況 vs 他 —— 落差一覽

| 項目 | 我們（tzutzu-ocr / pyexam.py） | 卷土重來 | 差距 |
|---|---|---|---|
| OCR 引擎 | Tesseract | PP-OCRv5 ONNX + OpenCC | **大**（已實測，見下） |
| 公式 | 壞掉 | MFD + RapidLaTeXOCR | **大** |
| 去手寫 | 無 | 自訓 dehand.onnx | **大** |
| 表格 | 亂碼 | 格線偵測重建 | 中 |
| 雙欄 | 投影切欄（已有） | 分隔線（相當） | 小 |
| Word 範本 | 陽春 docx | 茲茲 template.docx + buildlib | 中（我們 repo 已有 buildlib 可用） |
| 主引擎是否違反公司鐵律 | **是**（/api/exam-package 走 claude -p） | 否（全本地） | 要改 |
| 上線 | Vercel 前端 + Tailscale 後端 | 桌面安裝檔 + HF Spaces | 不同取向 |

### 已驗證：直接套他的 PP-OCRv5 模型跑你的百齡掃描卷
同一頁，Tesseract vs 他的 `det.onnx`+`rec.onnx`+dict（我今天實跑）：

- Tesseract：`圓往`、`最站距離`、表格全亂碼、雙欄交錯。
- **PP-OCRv5（他的模型）**：`圓柱浮體`✓、表格 `121.2 121.5 121.0 121.9 121.400 0.1533333`✓ 完全正確、
  `±` 認得、信心 0.9+、單欄 3.2 秒。

→ **光是把 OCR 引擎換成 PP-OCRv5，準確度就跳一大級。這是投報率最高的第一步。**

## 八、我們的優化藍圖：模仿 → 超越

分階段，每階段都「先抄他、再想哪裡能做得比他好」。

### 階段 1（投報率最高，可立即做）：換 OCR 引擎 Tesseract → PP-OCRv5
- `pyexam.py` 的 `ocr_page()` 改用 `rapidocr_onnxruntime` + 他的 `det/rec/dict` + OpenCC `s2twp` 轉繁。
- 保留我們已有的雙欄切割、裁圖。
- **比他更好的點**：PP-OCRv5 本身有版面排序，我們可以同時保留「自己的分隔線切欄」當備援，
  兩者取較合理者；並把每行信心值回傳前端，低於門檻的標紅讓人優先校對。

### 階段 2：公式 MFD + RapidLaTeXOCR
- 加 `requirements`：`rapid-latex-ocr`、`latex2mathml`；`get_models.py` 下載 `mfd.onnx`。
- 偵測公式框 → 轉 LaTeX → 以 `$...$` 塞回原位（我們輸出本就給 MathType Toggle TeX）。
- **比他更好的點**：把辨識信心低的公式自動列入「需人工確認」，附原圖截圖，不要默默塞錯的 LaTeX。

### 階段 3：去手寫
- 直接用他給的 `dehand.onnx`（我們沒有 `app/dehand.py`，要照 `dehand_eval.py` 的用法重建推論：
  150dpi、門檻 0.5、擦白）。
- **比他更好的點（資料）**：茲茲的乾淨版庫存比高中部更多（國中理化/數學），用 `pairs_build.py` 的方法
  自動生更多成對資料，**重訓一個召回更高、誤擦一樣低的 dehand v3**——這是我們真的可能超越他的地方。

### 階段 4：表格 / 附圖 / 卷頭規則
- 移植 OpenCV 格線偵測重建 Word 表格；連通域裁附圖；卷頭規則產檔名與橫幅。
- 我們 repo 已有 `exam-to-word` 的 `buildlib`，Word 範本這塊起點不輸他。

### 階段 5：上線守鐵律
- 後端 OCR 全本地化後，**移除 / 停用 `/api/exam-package`、`/api/generate` 的 `claude -p`**（違反鐵律）。
- 評估把引擎也包成桌面安裝檔（學他的 `desktop.py`），或丟 HF Spaces，取代 Tailscale 那套。

### 我們可能「超越」他的三個方向
1. **更多訓練資料**：用國中部的乾淨版庫存，重訓 dehand，召回更高。
2. **評測集更大**：延用 `ocr/run_eval.py`，建國中理化/數學的 testset，用數字驅動改進。
3. **接題庫 23 欄**：他做到「乾淨 Word」；我們可以在本地 OCR 之上，用**規則 + 小模型**補
   題型/單元/知識點的初步分類（不呼叫 API），再人工確認——這是他目前沒做、我們題庫系統需要的。

## 九、立即下一步（建議）
先做**階段 1**：把 `pyexam.py` 的 OCR 換成 PP-OCRv5 + OpenCC，把他給的三個檔放進 `ocr/models/`，
在你的真實考卷上用 `ocr/run_eval.py` 量準確度，確認跳級後，再往階段 2、3 推。

> 模型授權備忘：PP-OCRv5 / RapidLaTeXOCR 為 Apache-2.0；MFD(`mfd.onnx`) 內嵌 **AGPL-3.0**，
> 僅限茲茲內部使用，不可併入要對外散布的封閉產品。
