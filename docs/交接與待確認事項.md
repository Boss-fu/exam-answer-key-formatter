# 詳解製作工具 — 交接筆記（給接手的 Claude Code）

這份 bundle 是從雲端對話 session 打包出來的，請整份重新讀過一次，確認程式碼、SOP 規範、SKILL.md 三者彼此一致，並檢查是否還有沒改到的地方。

## 這個專案在做什麼
用 docx-js 產生國中理化/數學考卷的「詳解＋簡答」合併 Word 檔，套用固定的表格/字體/版面格式，數學公式用 `$...$` LaTeX 純文字（使用者用 MathType 的 Toggle TeX 轉換成真正的方程式物件）。詳細規則以 `理化數學詳解與簡答產出規範.md` 為準，`exam-answer-key-formatter/SKILL.md` 是給 Claude 用的技能版本（內容應與規範同步，但用詞更精簡）。

## 這個 bundle 裡有什麼
- `理化數學詳解與簡答產出規範.md`：完整規範文件（人看的版本）
- `exam-answer-key-formatter/SKILL.md`：Claude 技能版本（機器觸發用）
- `code/lib3.js`：docx-js 核心排版函式（表格、欄寬、字體、行高、分頁）
- `code/build_from_json.js`：讀 JSON 題目資料、呼叫 lib3.js 產出 .docx 的 CLI 工具

## 最近實測修正過、務必留意別改回去的地方
1. **表格無框線**：只在 TableCell 層級設 `borders: NONE` 不夠，Word 的預設 Table Grid 樣式仍會顯示框線。修正是連 `Table` 物件本身也要設 `borders`（top/bottom/left/right/insideHorizontal/insideVertical 全部 NONE），而且顏色不要用 `"auto"`（部分 Word 版本會判讀成黑色），改用固定的 `"FFFFFF"`。這是使用者在自己電腦用真正的 Word 開檔才發現的，LibreOffice 預覽看不出來。
2. **字體**：中文統一用 `DFPYuanMedium-B5`（取代之前的華康細圓體(P)/華康細圓體兩種），英文/數字用 `Times New Roman`。`font: { ascii, hAnsi, eastAsia, cs }` 四個都要設。
3. **LaTeX 公式定案為單一錢號 `$...$`**：中途曾一度改成雙錢號 `$$...$$`，後來使用者確認雙錢號在聊天介面傳輸時容易被系統的數學符號渲染吃掉字元，明確要求改回單一錢號。**這個已經是最終定案，不要再改成雙錢號。**
4. **欄寬**：題號0.7cm／標籤2.2cm／字母0.9cm／內容約14.2cm（18cm版心減前三欄），這是實測使用者真實字型環境才校正出來的，比早期版本寬，避免「【答案】」「(A)」被擠到自動換行。
5. **行高**：段落行高用 **1.5 倍行高**（docx-js `lineRule:"auto"`、`line:360`）。曾短暫改成 Exactly 12pt（較密），但 MathType 的分數／上下標在 Exactly 12pt 下會上下擠在一起、難閱讀，使用者要求改回 1.5 倍行高，目前以此為準。
6. **分頁**：同一題不可被拆到兩頁，用 `cantSplit`（TableRow）+ `keepNext`（Paragraph）達成，不要用固定行數估算插分頁符。

## 這次重新產出時發現、可能還沒完全 catch 的坑
- 早期一輪「幫公式加 `$...$`」的掃描是用「是否含數字」當判斷條件，結果漏掉了完全由英文變數組成、沒有數字的算式（例如 `N≈(M×n)/(R)` 這種）。後來擴大掃描 `=`、`≈`、括號分數 `(\d+)/(\d+)` 等 pattern 才抓到。**建議：如果之後再處理新的一批考卷題目，公式掃描邏輯不能只靠有沒有數字判斷，要涵蓋等號/約等於號/分數/上下標/希臘字母/度數符號等情況。**
- 曾經在詳解文字裡出現「CJK 字元包在 LaTeX 下標裡」的寫法（例如 `F_{A,水}`），這種混排可能會讓使用者真實 Word 裡 MathType 的 Toggle TeX 轉換失敗（跑出空白方框或亂碼）。已經改寫成不把中文包進下標的版本，但這是一個一般性風險，之後新產出的詳解也要注意避免這個模式。
- 交付前的【答案】欄位比對，不能用「文字裡有沒有出現『正確』兩個字」去判斷，因為選項理由裡常出現「雖然...正確，但...」這種句子；要判斷選項是不是**以「正確」開頭**。
